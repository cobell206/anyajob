# Architecture — current state (serverless)

The single source of truth for **how production runs today**. If another doc
disagrees with this one, this one is right (the migration off EC2 finished
2026-07; see `SERVERLESS-TRANSITION.md` for the blow-by-blow history).

One-line summary: **the whole Express app runs as a Lambda behind an API
Gateway HTTP API, fronted by Cloudflare (DNS + Access SSO); all state lives in
S3; crons run on EventBridge. There is no server to SSH into.**

## The shape of it

```
        Cloudflare (DNS + Access SSO, Full-strict TLS)
                        │  injects Cf-Access-Jwt-Assertion
                        ▼
        API Gateway HTTP API "anyajob-web"
          $default → JWT authorizer (Cloudflare Access)
                        │
          ┌─────────────┴───────────────┐
          ▼                              ▼
   Lambda anyajob-web           (async invoke)
   src/lambda.handler  ───────► Lambda anyajob-scoring-worker
   Express via serverless-http   src/worker.handler (résumé scoring, ~54s)
          │                              │
          └───────────┬──────────────────┘
                      ▼
        S3: anyajob-data (JSON "DB")   S3: anyajob-docs (uploaded résumés/covers)

   EventBridge Scheduler ──► Lambda anyajob-cron (src/cron.handler)
     CronDaily   6am ET daily     → job=daily    (scrape → score → summaries)
     CronDiscover 7am ET Mon/Thu  → job=discover (source discovery)
```

All three Lambdas run from **one shared code asset** (`infra/.app-bundle`,
built by `scripts/build-lambda-bundle.sh`) — same repo, same code, different
handler + env. Account `378962034618`, region `us-east-1`, all Lambdas
`nodejs20` / `x86_64`.

## Components

| Thing | Name / id | Notes |
|---|---|---|
| Web Lambda | `anyajob-web` | `src/lambda.handler`; Express wrapped by `serverless-http`; 30s / 512MB |
| Scoring worker | `anyajob-scoring-worker` | `src/worker.handler`; 300s / 512MB; async-invoked because résumé scoring (~54s) exceeds API GW's **30s** cap |
| Cron Lambda | `anyajob-cron` | `src/cron.handler`; 900s / 1024MB; dispatches `{job}` → daily/discover/weekly |
| HTTP API | `anyajob-web` | `$default` → web Lambda; throttle burst 20 / rate 10 |
| Authorizer | `cloudflare-access` | `HttpJwtAuthorizer`; issuer `https://anyalawgirly.cloudflareaccess.com`, AUD `462fb46b…e12f189`, header `Cf-Access-Jwt-Assertion`. A request straight to the execute-api URL with no Access JWT → **401** |
| Custom domain | `jobs.anyalawgirly.com` | ACM cert (DNS-validated on Cloudflare, **manual CNAME**) + API GW DomainName + ApiMapping. Cloudflare proxies DNS → the `WebApiRegionalDomain` output, Full-strict |
| Data bucket | `anyajob-data` | JSON "database", one object per `data/*.json` file; **versioned**, `RETAIN`; noncurrent versions expire 30d |
| Docs bucket | `anyajob-docs` | uploaded résumés/cover letters, keyed `{fingerprint}/{file}`; versioned, `RETAIN` |
| Schedules | `CronDaily`, `CronDiscover` | EventBridge `CfnSchedule`, tz **America/New_York** (fixes the old UTC crons' DST drift) |
| Alarms | `anyajob-cron-errors`, `anyajob-cron-duration-near-cap` | → SNS `anyajob-cron-alarms` → email `cobell206@gmail.com`. Duration ≥13min = "daily has outgrown Lambda's 15-min cap, move to Fargate" |
| Deploy role | `anyajob-github-deploy` | GitHub OIDC; assumes the CDK bootstrap roles + reads the Anthropic SSM param. No stored AWS keys |

There is **no weekly schedule**: `weekly.js` only sends the (unused) digest
email, and the weekly reflection is generated by `daily.js` on Sundays. The
`weekly` dispatch stays in `cron.js` so re-enabling is a one-liner.

## Storage seam

`src/store.js` is **the** seam — every read/write of a `data/*.json` file
funnels through it. `io.js` and `atomic.js` are thin re-exports (kept so old
imports don't break). Backend is chosen by env:

- `STORAGE=fs` (default) — local disk `data/`, for dev.
- `STORAGE=s3` — the `anyajob-data` bucket, for prod (set in the Lambda env).

Data JSON is keyed by **basename** (`listings.json`, `feedback.json`, …).
Uploaded binaries go through `src/docstore.js` → `anyajob-docs`, keyed
`{fingerprint}/{file}`. **Logs are not in S3.**

## Deploy

Push to `main` → **`.github/workflows/deploy-infra.yml`**:

1. `test` job (node20): `npm ci` + `npm test`.
2. `deploy` job (node24 — `infra/` is ESM type-stripped and needs node ≥22):
   OIDC-assume `anyajob-github-deploy` → `npm run bundle:lambda` → `cdk deploy`.

`paths-ignore: *.md`, so **doc-only pushes don't deploy.** The CDK stack is
`AnyaJobStack` (`infra/lib/anyajob-stack.ts`).

**Anthropic key**: lives in SSM SecureString `/anyajob/anthropic-api-key`.
CloudFormation rejects `{{resolve:ssm-secure:…}}` in a Lambda env var, so it's
passed as a **noEcho CfnParameter** (`AnthropicApiKey`) at deploy time. To
deploy by hand:

```bash
npm run bundle:lambda
cd infra && npm ci
npx cdk deploy --require-approval never \
  --parameters AnthropicApiKey="$(aws ssm get-parameter \
    --name /anyajob/anthropic-api-key --with-decryption --region us-east-1 \
    --query Parameter.Value --output text)"
```

## Logs & debugging

Lambda writes to **CloudWatch Logs**, one group per function:
`/aws/lambda/anyajob-web`, `/aws/lambda/anyajob-cron`,
`/aws/lambda/anyajob-scoring-worker`. That's the source of truth now.

> The old in-app `/api/logs/*` file-tailing endpoints read a `server.log` on
> disk — that pattern is EC2-only; Lambda's filesystem is ephemeral, so those
> endpoints have nothing persistent to read in prod. Use CloudWatch.

## The Anthropic native-dep gotcha

`pdf-parse` (résumé text extraction) needs `@napi-rs/canvas` for `DOMMatrix`,
which has a **native binary** npm can't install on macOS for the linux target.
`build-lambda-bundle.sh` fetches the `@napi-rs/canvas-linux-x64-gnu` prebuilt
matching the wrapper version — this is why the Lambda arch is pinned `x86_64`
and why there's a custom bundle script instead of a plain `cdk` asset.

## What's dead / vestigial

EC2 is **stopped** (instance `i-0fb0c9e04b10c9993`; EBS retained as rollback
until termination). These workflows are EC2-era or one-shot migrations and no
longer do anything useful: `deploy.yml` ("Deploy to EC2" — still fires on push
but fails harmlessly), `fetch-logs.yml`, `verify-live.yml`,
`disable-ec2-crons.yml`, `disable-backup-cron.yml`, `cutover-to-s3.yml`,
`s3-migrate.yml`, `read-cron-env.yml`, `check-daily-runtime.yml`,
`migrate-degree.yml`, `migrate-location.yml`, `clear-parse-failed.yml`. Only
**`deploy-infra.yml`** is a live recurring workflow.

Access free. (Was ~$8–10/mo on the always-on EC2 t3.micro.)
